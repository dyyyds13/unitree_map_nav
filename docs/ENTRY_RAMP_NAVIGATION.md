# 本地2号管道入口坡：自主导航修复

适用于用户授权的 `--task-fixture --pipe-ramp entry` 本地场景。官方资源和原地图不变；不是正式比赛成绩或实物验证。

## 停车原因与处理

用户记录 `output/local-20261115-231501` 在碎石区最后的接近点停滞。该点原来落在新入口坡中间，要求机器人在坡上转向；导航坡度上限14°也低于入口坡实际约18.7°，且原管道路线仍声明22厘米直角台阶能力要求。

默认本地入口场景现在选择 `configs/local-entry-ramp-route.json`，先在坡前平地对齐，再沿管道中心线进入。官方布局继续使用原路线及原台阶保护。新路线以起点相对地图声明小范围坡度分类上限26°，给稀疏观测误差留余量；不改变全局14°限制、8厘米台阶限制、碰撞体、净空或水域检查，也不代表实物具备26°爬坡能力。入口段速度上限0.22m/s，普通路段仍0.5m/s。明确速度上限会参与DWA速度采样边界，避免关节里程计瞬时超限时所有前进候选被删掉。

完整接近试验还发现约15厘米的定位/路线横向偏差。仅对本地管道声明的直通走廊，A*改用当前观测地图上的完整定向机身占地，与DWA采用相同的额外2厘米缓冲；这是避开圆盘膨胀重复封路的姿态检查，不改地面/障碍/水域单元。搜索限于机器人周围1.6米，仍逐个检查机身支撑和足部水域。航点容差20厘米允许围绕路线先验选择实测安全通道，固定航点不能强迫机器人跨过实测坡边。

慢步态的瞬时关节里程计在10Hz采样时会出现摆腿混叠，DWA动态窗口随后反复选到微小反向速度。管道走廊的规划平移速度现在使用0.2～0.6秒接受定位窗口的位移估计，拒绝过大跳变；其他赛段继续原速度来源。该窗口由已接受雷达定位构成，不读取真实根速度。它只改变规划速度估计，仍保留实际碰撞和制动路径检查。

进入管道段时，使用当前及后续传感器观测建立独立地形子图，保留此前全局图和水域观测；回环重建也只在这个子图内重放入口之后的关键帧。这样不会将前段上、下坡累计的高程参考继续带入入口。新图只有测到的支撑面和障碍物，未观测区域保持不可通行，原全局图未清除。该子图目前覆盖入口和管内停车验收，出口/后续阶段仍受能力保护。

专项运行又发现地板/顶壁混淆：圆管顶壁有时被连接进地面点集，覆盖已有地板；纠正地板后，旧的相对净空值还会残留。现仅在声明的特殊坡区域保护已有较低支撑面，较高回波仍参加碰撞/净空检查；天花板保存绝对高度，地板更新后重新计算净空。实际石块、过陡表面、宽缺口仍阻断通行。

MPC在平地与坡面交接处改用每脚查询的有界雷达地面插值，机体参考由脚下支撑高度拟合。特殊坡区域使用1.5Hz、75%支撑占空比的开源对角步态，以及随观测坡面法向旋转的摩擦约束，摩擦系数仍0.4；高质量雷达位移仅在此区域辅助修正纵向打滑估计。普通赛段保留原2.5Hz步态和原MPC求解器。平地SE(2)脱困不在这个陡坡区域旋转执行。

机器人关节力矩仍由开源凸MPC求解后限幅，仿真仅 `mj_step` 进行状态转移。导航/MPC不读取真实根位姿或目标真值；真值只用于传感器、渲染、独立诊断与测试停止条件。

`scripts/check_entry_ramp.py` 是明确标记的自主入口专项：仅初始重置在管道前，随后由公共Autonomy控制，逐2毫秒评价碰撞/跌倒/进水/越界。在管内到达受保护出口航点后，确认至少2秒停车及1秒净位移速度低于0.03m/s。它不跳过正式运行中的赛段，也不能作为整圈通过证据。默认不写视频、原始传感器、物理大档案或场景二进制。

```bash
.venv/bin/python scripts/check_entry_ramp.py --output output/entry-check-new
.venv/bin/python scripts/check_entry_ramp.py --spawn 7.15 6.20 --seed 1 --output output/entry-check-offset-new
```
