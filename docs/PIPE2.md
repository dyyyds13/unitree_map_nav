## 当前实现

注意：当前工作区入口裁剪已是前进0.45m/s、倒退0.3m/s，该值不同于历史`pipe2-stage-10`的0.045m/s，尚未做新的台阶物理验收。本轮普通行走0.5m/s测试保留了它，但不据此声称高速越阶通过。

`configs/official-course-route.json`已改为碎石区绕行后接近2号西口，向东穿管，经过出口下降门槛，再进入终点。起点仍是上坡前的`(0.8,0.8)`。路线是公开固定地图的人工先验，不包含球坐标。

新增实验性MPC越阶适配：在关节/IMU里程计坐标系中，雷达必须连续观察到上层平面和前侧台阶面，才确认约12～27厘米的单台阶。进入阶段使用1Hz低频对角步态、先抬脚再平移的轨迹，前后腿采用不同的迈上时机，机身参考高度和俯仰随估计台阶变化。早期逐腿慢爬出现侧翻，未作为最终方案。历史通过版本上台阶阶段限速0.045m/s；进入后恢复普通MPC步态，使用测得的航向和关节里程计修正运动，下降门槛允许拟合不超过30°的局部支持面。

这是控制器开发功能，通过`ConvexMPC.enable_curb()`显式启用；默认自主运行和实物SDK不调用它。单段脚本给定纵向速度和停止距离，不承担A*/DWA的避障职责。不能据此声称整套自主系统已经会过2号管道。

## 单独运行

在项目根目录执行，每次使用新目录：

```bash
.venv/bin/python scripts/test_pipe2_controller.py --output output/my-pipe2-stage --seconds 85 --speed .09
```

该脚本在管道前`(8.1,6.22)`初始化一次，因此视频始终标注STAGE TEST。物理步进仅由关节力矩和`mj_step`推进，没有运行中根位姿覆盖、外力拖动或地图几何改动。真值只用于渲染、接触/跌倒等只读诊断和停止检查，控制反馈来自传感器。视频右侧为前视相机；管顶遮住外部视角时，可从前视画面查看管内通行。

输出`simulation.mp4`、`physics.npz`、`diagnostics.json`、`summary.json`。检查`stage_pass`，不能仅看`pipe2_exited`或进程正常结束。

`pipe2-stage-10/inspection.mp4`是从存档物理状态离线绘制的观察录像，上半管壳仅在渲染器绘制列表中显示透明，便于看清机器狗；右上角相机仍显示实心管顶。它不改变模型、碰撞、控制或原始物理数据，`simulation.mp4`原录像保持原样。可用`python scripts/render_pipe2_inspection.py output/pipe2-stage-10`为其他同格式单段记录生成新回放（须使用.venv中的Python，输出文件不能已存在）。
