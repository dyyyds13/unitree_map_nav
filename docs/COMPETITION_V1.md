# 比赛后续流程：模块、运行与验收

按用户要求，默认全场模式强制依次完成：上坡（L1）→坡顶及下坡→S弯→死胡同进入、观察并退出→碎石区域避石通行→圆形2号管道→终点区域找球报位并结束。实物使用厂家行走接口，MuJoCo使用开源凸MPC；两者共用感知与决策代码，不增加ROS 2或训练依赖。

## 实现范围

| 环节 | 本轮实现 | 验收边界 |
|---|---|---|
| 上坡、坡顶、下坡 | 雷达地面去除后的定位、地形相对高度/坡度/净空、MPC随坡适配 | 长测检查实际接触的地形阶段；不能用机身升高代替通过整坡 |
| 水洼 | RGB颜色候选，经标定与地面雷达确认后投影到禁行栅格 | 当前针对场景中可见的青蓝色水面，不是通用真实水体识别器 |
| 乱石与隔墙 | 原有占据栅格、A*和DWA，保留禁行与制动距离检查 | 不将碎石当可踩踏地面，不读取场景几何ID规划 |
| 死胡同和窄通道 | 局部SE(2)搜索同时侧移/转向，逐段检查机身与落脚包络；失败目标暂缓重试 | 没有安全路线就停车或搜索其他区域，不强推机器人穿障 |
| 隧道 | 地面相对净空与完整有朝向机身检查 | 低屋顶拒绝测试已加入；具体官方隧道能否通过仍需动力学结果 |
| 黑白球 | 圆弧、纹理、几何定位、多帧去重；弱候选保留换视角，至少两次近期强证据才报位 | 不能确认时不报；部分遮挡的合成检测通过不等于真实球召回率 |
| 搜索与返程 | 前沿探索；已声明目标配额满足或时间预留触发返程；不可达终点继续探索 | 未知实物默认目标配额0，不假定全场只有一个球 |
| 终点结束 | 可达性检查、重新面对标识、低速停稳持续1秒、一次finish | ArUco 42是实验代理；正式赛方终点和信号合同尚未适配 |
| 本地诊断 | 接触、足端入水、越界、跌倒、报位误差、真实终点范围与停止原因 | 只读真值只在评估器中使用；不是官方评分公式 |

## 从原起点运行

必须进入项目目录；每次换一个新的输出目录：

```bash
cd /home/l/下载/robotics-bench-go2-competition-training-resources
.venv/bin/go2-rescue mujoco --viewer --task-fixture --course-policy ordered --seconds 600 --output output/my-course-v1 --record
```

默认机器人起点固定为上坡路线前的世界坐标`(0.8,0.8)`。`--spawn`仅用于明确指定的局部测试；日志、视频和summary.run_scope会标明ORIGINAL START或STAGE START，局部测试不能通过full_course_pass。默认球在远端终点区域，不是起点附近。官方静态几何保持原样，动态球和实验标识属于明确标注的本地测试场景。
`--seconds`是仿真时间上限；感知和恢复搜索可能使墙钟耗时显著更长。到时退出不是任务成功，查看`mission_complete`和`stop_reason`。
有窗口时停止后保留最终画面；关闭窗口或Ctrl+C退出。自动关闭可加`--close-viewer-on-stop`。无窗口时去掉`--viewer`。

定位的`map_start`原点在预热后第一帧被接受的雷达观测处。仿真评估器在start时记录对应真值变换，仅用于误差计算；算法不接收该变换。

## 固定地图的顺序路线

`configs/official-course-route.json`是人工编写的公开固定地图路线先验，坐标相对于原起点；不包含球坐标，不由仿真真值自动生成。定位仍来自雷达、关节和IMU，A*／DWA只能穿过已观测且满足完整机身安全检查的地面。它不能代表未知随机布局的自主泛化能力。

每段必须经过检查点；坡道还需测得高度变化和俯仰，死胡同需前方雷达确认、停留并倒退退出，管道需观察屋顶及通过距离。目标配额、提前看到终点、接近时间上限都不能跳过前置环节。普通转场点允许从旁边安全通过；宽阔坡顶转场的门宽半径0.6m，S弯及倒退对应转角采用0.35m通过区域并检查朝向。区域内的SE(2)姿态搜索仍逐段验证完整机身碰撞。窄口中心线、死胡同深处和停留点保持小容差，不能用大区域跳过前置阶段。

用户已明确必须穿过圆形2号管道。路线已改为从西口进入、沿管内向东行走、经过下降门槛出去；不能用3号通道代替。物理评估另要求2号内地面接触、实际横穿距离和东侧退出。约22厘米入口台阶的低频MPC专项尚在验证，自主接入未完成；默认全场模式到此停车并说明缺少已验证越阶能力，不跳过阶段。详见[2号管道专项](PIPE2.md)。官方静态地图、坡道、墙、碎石与管道均不修改。

`--course-policy auto`默认对远端全场启用ordered；近起点短回归保持explore。指定局部起点时必须显式用`--course-policy explore`，不能产生整圈通过结果。

坡道和S弯保留10厘米地形栅格；死胡同退出后，使用已录制的关键帧观测和估计位姿重建5厘米地图，供窄口与后半程规划。地图细化不读取仿真真值，并重新投影已观测水面。定位采用点到线雷达匹配；稳定IMU朝向可作为起点相对航向约束，避免稀疏点云匹配在窄口积累旋转漂移。未知实物默认不启用该航向假设。安全缓冲发生少量侵入时，允许经过逐段检查、限速0.05m/s的短距离退出；物理机身和足端水面约束始终保留，不以清空地图解除卡住。U形死胡同旁的窄口单独声明`narrow_passage`，历史通过配置额外安全余量为2厘米、速度上限0.08m/s；当前前进上限已可配置，仿真默认0.5m/s，现有工作区余量表达式保留为`min(safety_margin,.2)`（默认仿真实际5厘米），见[速度说明](SPEED.md)，保持严格朝向；其余区域仍用5厘米额外余量。窄口设置经完整机身/水面拒绝回归验证，实际通过仍需长测。

## 查看运行过程

```bash
tail -f output/my-course-v1/runtime.jsonl
```

- 每2仿真秒输出状态与速度；开始、目标、结束、停止原因单独记录。
- 每20仿真秒更新`progress.json`、`map.npz`、`map.png`和`live-preview.png`；这些是最近一次快照，时间以文件中的时间戳为准。
- 退出时写`summary.json`、完整`simulation.mp4`、轨迹和物理记录。正常finish仍可能因误报、碰撞或入水未通过本地检查。
- `full_course_pass`还要求原起点、全部七段顺序完成及只读物理轨迹复核，阶段测试和仅终点成功均不能通过。
- `evaluation.local_task_pass`要求完成、在实际终点区域、目标误差≤0.5m，无跌倒、障碍接触、入水和越界；不代替赛方评分。

水洼与墙的碰撞语义不同：墙按整个机身包络检查；水按配置的足端接触包络检查，允许机身悬空部分经过水边。仿真包络只适用于当前Go2模型，未知实物没有默认启用这些缩小后的尺寸。物理评估另外用实际足端位置检查入水。

## 重复验收

```bash
.venv/bin/python scripts/validate_competition.py --output output/course-validation --seconds 600 --seeds 0 1 2 --record
.venv/bin/python -m pytest -q
```

脚本依次运行并生成`validation.json`和`validation.md`；任一未通过返回非零状态。种子目前只改变传感器噪声，**不是不同随机赛场布局**，不能据此宣称跨布局泛化或80%成功率。

历史原起点运行`ordered-course-13`走的是3号通道；当时七段完成并结束、0物理违规，但原记录有一次额外错误报位，严格验收False。该记录不满足当前必须2号的要求。已声明目标数的上报预算补丁通过226帧组件回放，只报一次、误差约6.9厘米，尚未另做补丁后物理全程。此约束不解决未知目标数的识别精度。

当前实测结论与未解决问题以[验证报告](VALIDATION.md)和[当前状态](CURRENT_STATE.md)为准。硬件型号/雷达驱动/标定未知，未进行实机运动验证；正式世界坐标、目标总数、结束信号与评分权重仍须赛方合同明确。
